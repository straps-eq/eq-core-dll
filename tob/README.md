# eq-core-dll (ToB)

A `dinput8.dll` proxy for the 64-bit EverQuest ToB client (`eqgame.exe` build `Sep 11 2025 11:54:10`).
It forwards DirectInput to the system DLL and applies opt-in client patches chosen in `dinput8.ini`.

Every patch site is found by byte signature, and its original bytes are checked before anything is written.
If a signature doesn't match on a given client build, that feature is skipped and logged to `dinput8.log`,
so a different build is never patched blindly. Features can also hook a client function (inline x64 hook:
the function's first bytes go to a trampoline and are replaced by a jump to our code); hook sites and the
client functions/globals a hook uses are found and checked the same way.

## Features (the shipped `dinput8.ini` turns the safe ones on)

| `dinput8.ini` key | What it does |
|---|---|
| `SoloLDoN` | LDoN adventure requests without a group (server must allow solo) |
| `NoDoubleDamage` | Stops the client applying melee hits to your own HP twice (bouncing HP bar, knocked out at about half health) |
| `MaxHPAbove10M` | Removes the client's three 10,000,000 HP caps |
| `AAPre51` | AA window usable below level 51 |
| `AAPre51Inventory` | Shows AA exp on the inventory window below 51 |
| `IllegalAugments` | Allows augment combinations the player can't use |
| `NoFoodDrinkSpam` | No client hunger/thirst processing or messages |
| `NoPatchme` | Starts `eqgame.exe` without the `patchme` argument |
| `ConNameTags` | Colours NPC name tags by con colour (pets, mercenaries, PCs and GM mode keep the client's colours; your current target keeps the client's blinking name). Tags refresh when a spawn's name is rebuilt or the target changes, and all NPCs are re-coloured after you level |
| `MapSpawns` | Draws spawns on the map window as labelled dots (NPCs in con colour, grey cons in a darker grey that reads on the parchment; players, group members, pets, mercenaries and corpses in their own colours) plus a line to your target. Only spawns the client itself shows you: nothing untargetable, invisible to you, or a trigger/trap/object. Nearest `MaxLabels` spawns; filters, colours and font under `[Map]` in `dinput8.ini` (`LabelSize` 1-3: the map's draw only carries the first three UI fonts, so larger text would need our own draw). Labels live on map layer 3 by default, so the map's layer buttons and Z filter apply |
| `BuffTooltips` | Buff, song and target buff tooltips show the caster (when the server sent one), the remaining time as the client formats it, one line per effect in words ("Increase Hitpoints by 120 (L1) to 450 (L60) per tick", values from the client's own calculator over the spell's level range) and the cure counters a spell carries ("needs cure: 3 poison"). Text is re-set only when it changes; options under `[Buffs]` in `dinput8.ini` |
| `TargetDistance` | One line in the Target window under the HP gauge: the target's level, race and class ("8 Orc Warrior") in its con colour on the left and the 3D distance ("107.01") right-aligned with the font's own width measure. Drawn from the window's own Draw, so windows above it cover it, clipped to its client area and placed in the first row below the gauge and its labels (`AutoPlace`); colour, font and offsets under `[TargetDistance]`. Uses the client's own text routine, so it works with any UI skin. No line-of-sight marker: the client's LOS test has not been located |
| `Hud` | A fixed text block at `[Hud]` `X`,`Y`: your loc (Y, X, Z like `/loc`), zone long name, target name and distance, FPS (measured from frame deltas) and the local clock. Each line has its own on/off key; colour and font under `[Hud]`. Draws only while in game |
| `ItemDisplayExtras` | Adds text below the item window's own description (the client's "Effect:" lines, lore and server item information stay): for each spell on the item its name and "Spell Effect: <description>" when the window did not print that description itself (it does, after its "Effect:" lines, for most items); a block with item id, icon id, stackable count, value in pp/gp/sp/cp, tribute values, weapon ratio and efficiency, lore text (when it differs from the name), "Procs at level" / "Clickable at level" (red when above your level), required/recommended level, container details and how long a clicky still has to cool down; then for every click/proc/worn/focus/scroll/blessing effect a "Spell Info for <kind> effect" block with the spell's id and duration, recovery and recast, range, resist and one "Slot N:" line per effect in words (values from the client's own calculator at the effect's cast level). Options and colours under `[ItemDisplay]` |
| `SpellWindowExtras` | Adds to the spell window (a buff's right-click "Show Spell Information", spell links in items and chat, spell gems) below the client's own text: "Spell Effect: <description>" when the client did not print it, then one block with "ID" (plus "Duration", "Range" and resist only when the client's text lacks them, or always with `ShowDuplicates=1`), "RecoveryTime / RecastTime", one "Slot N:" line per effect in words (a level range when the value scales, or the cast level the window was opened with), the classes that get the spell with their levels, category, subcategory and spell icon. Options under `[SpellWindow]` |
| `FloatingCombatText` | Floating combat text as in EverQuest Legends: damage numbers and the words Miss, Block, Parry, Riposte, Dodge, INVULNERABLE and Rune (melee only; a landed spell is not a miss) rise from the head of the spawn that was hit (a hit or miss whose chat line is set to Hide in the Chat tab gets none either; `[FCT] FollowChatFilters=0` shows them anyway), heals show as green numbers over the healed spawn (`HealText`; from the heal messages the server sends today, or from the client's own heal message OP_CombatText64 when the server sends it, which adds overheal "N (M)" and crits), in world space (they stay where the hit happened and are re-projected every frame), at a random angle and speed pulled down by gravity, with Legends' defaults. Client-only: fed by the OP_Damage packets the server already sends (hook on the OP_Damage handler, after the client has handled the packet) and drawn as 3D world text through the engine's own string sprite (the class name tags use), so it scales with distance like Legends (`[FCT]` `Render3D`, `LetterScale`, `MinPx`, `Occlude`; if the engine checks fail it falls back to 2D UI fonts and says so in `dinput8.log`). Groups as in Legends (Self: hits on you; You: your hits; Other: everyone else's, your pet's included, only within 200 units like the chat window), each with a text mode (None, Full, Abbreviated, DMG Only) and font scale; colours are your chat colours, crits twice the size, numbers live 4 s (crits 5 s) and words 2 s, nothing beyond 200 units or behind the camera, everything cleared on zoning. Pet hits the server sends twice are shown once. Settings under `[FloatingCombat]` (Legends' key names) and DLL extras under `[FCT]`; `Ctrl+Shift+F` turns it off and on. Not in yet: heals, Ding!, Out of Range, Fizzle, Missed Note, Resist, skill-up and loot/sell texts (their ToB handlers are not mapped), the pet/merc colour variants and the DoT green |
| `FCTOptionsPage` | Legends' "Combat Text" tab in the Options window (between Display and Mouse): Show Floating Combat Text, Sell/Loot Text, velocity, angle and gravity sliders with Legends' percent labels (the slider position; `[FCT] SliderLabels=value` shows the Extras sliders' values instead), and per group (You / Self / Other) a font scale slider, a text-mode combobox and a colour combobox (chat colour or a preset; other hex values stay in the ini as "Custom (ini)"). An "Extras" group sets the DLL-only `[FCT]` keys: outline, fade, pet de-dup, max texts, toggle key (presets, "Custom (ini)" for others), Other range, font step and start height. Every change is saved to `[FloatingCombat]` in `dinput8.ini` at once (`eqclient.ini` is not touched) and the page is re-filled from it whenever the tab is selected. Needs the patched `uifiles\default\EQUI_OptionsWindow.xml` (the page uses ToB templates only; apply the same block to a custom skin). Without it the feature stays silent. Requires `FloatingCombatText` |
| `Nameplates` | Legends-style bars under names: an HP bar (red), then a cast bar (purple, emptying as the cast ends; a full red bar for half a second when the cast is interrupted) or a mana bar (blue), sized from the client's own name text and hung under it, plus a flashing HP bar (shown even at full health) on NPCs that are on you (`ThreatDisplay` 1) or on you, your group or your pet (2); Legends draws a frame instead: exact for your target (OP_TargetHoTT), otherwise "swung at you within `ThreatHoldMs`". Shown on every hurt spawn and on your target, within `DrawDistance`, only when the client draws the spawn's name, and with `Occlude=1` (default) the bars are drawn in the engine's own depth-tested name pass at the name's depth, so walls hide a bar pixel for pixel exactly like its name (falls back to 2D bars with a visibility check if the engine checks fail; `DepthBias`), never on corpses, invisible or untargetable spawns or spawns whose names are hidden; your own bars follow the Self options. Drawn on top of the world from the same per-frame point as `Hud` with the renderer's own quad and line calls. Untargeted NPCs only show bars when the server sends their HP to nearby ToB clients (rule `Character:ToBNameplateVitalsRange` above 0); otherwise bars appear on your target, group and extended targets. Settings under `[NameplateOptions]` (Legends' key names). `Size` also scales the bars, since ToB's name cannot be resized. With `HpText` / `CastSpellName` on, the HP % and spell name labels are drawn in the same depth-tested name pass (walls hide them with the bars; outline or shadow from `FontOutline` / `FontShadow`). `SelfName=0` hides your own name (third person) and `CorpseNames=0` hides corpse names: both go through the client's own "no name" path when it builds a name, so they take effect at once and survive zoning. Not ported: faction icons, AttachToHead |
| `NameplateOptionsPage` | Legends' "Nameplates" tab in the Options window (after Combat Text): the bar toggles, shadow/outline, Con Color (switches `ConNameTags` live and saves `[Features] ConNameTags`), Show Corpse / Self / PC / NPC / Pet / Pet Owner / Merc / Merc Owner Names (PC to Merc Owner are the client's own Display settings: a click here is a Display click, applied and saved to `eqclient.ini`, and the boxes follow `/shownpcnames`), Draw Distance and Size sliders with percent labels, Name Filters (the client's own `/shownames` level; names rebuild at once) and Threat Indicators, plus an Extras group (spell name, HP %, HP by con, threat memory, threat flash colour). Saves to `[NameplateOptions]` in `dinput8.ini`. Needs the patched `uifiles\default\EQUI_OptionsWindow.xml`; without it the feature stays silent |
| `AdvLootActions` | Store All / Sell All buttons on the Advanced Loot window's Personal panel (needs the patched `uifiles\default\EQUI_AdvancedLootWnd.xml`) and "Sell / Store this item" on its right-click menu. Store puts tradeskill stacks in the Tradeskill Depot and other items in the Dragon's Hoard; Sell pays merchant value. Requests go through the client's own loot request, so rows disappear when the server answers. Two checkboxes at the bottom of the window: Shift for the All buttons (`ShiftForAll`, default on) and auto actions (`AutoFilters`): right-click "Auto-sell / Auto-store this item" and later drops of that item are handled as they appear, once per corpse, never on NO TRADE items unless `AutoNoTrade=1`, saved per character in `userdata\eqcore_advloot_<Character>.ini`. With `AutoFilters` on, the Personal loot list gets AS / ST checkbox columns after NPC Name (same patched `EQUI_AdvancedLootWnd.xml`) that set or clear the item's auto action right there, and the Edit Loot Filters window gets AS / ST columns after Remove (needs the shipped `uifiles\default\EQUI_LootFiltersWnd.xml`) that show and change the per-item auto-sell / auto-store actions (mutually exclusive; both off clears the action); items with only an auto action get a row too, following the search text and "Max search results"; Remove also clears the action, a row whose AN/AG/NV boxes are all cleared stays while an auto action remains, and Merge / Replace Filters from another character also merges / replaces that character's auto actions. Sales and loots show the item over the corpse through `FloatingCombatText` ("<item> (Xp Yg Zs Wc)" for a sale). Only active on a server that announces the feature; otherwise the window is stock. Legends' Merge is left out. Options under `[AdvLoot]` |

Old-model horses need no patch on ToB: set `AllowPreLuclinMountRiders=1` under `[Defaults]` in `eqclient.ini`
(Options window, "Toggle Display of Pre-Luclin Characters on Mounts").

## What needs the server

Most features are client-only and work on any server. These need something from the server:

| `dinput8.ini` key | Server side |
|---|---|
| `SoloLDoN` | The server must accept LDoN adventure requests from a player without a group. Otherwise the request is refused server-side. |
| `AAPre51`, `AAPre51Inventory` | The client patch only unlocks the window. The server must actually award AA experience and points below level 51, which stock EQEmu does not. |
| `Nameplates` | HP and mana bars on NPCs you have not targeted need the server to send their HP and mana percent to nearby ToB clients. That is a server change not in stock EQEmu (rule `Character:ToBNameplateVitalsRange`, a range in units; 0 = off). Without it, bars only fill for your target, group members and extended targets, which is what stock EQEmu sends. Cast bars, the interrupt flash and the threat frame use packets every server already sends. |
| `AdvLootActions` | The server must announce the feature (it sends its capabilities after each loot sync) and handle the sell / store actions. Stock EQEmu does neither, so on a stock server the loot window stays stock. |
| `BuffTooltips` | The "Caster:" line only appears when the server includes the caster's name in the buff data. |

`FloatingCombatText` needs nothing extra: it uses the damage packets every server sends (the pet-owner duplicate that EQEmu sends for pet hits is filtered out client-side).

The options tabs (`FCTOptionsPage`, `NameplateOptionsPage`) need a patched `uifiles\default\EQUI_OptionsWindow.xml` on the client, not a server change. The AS / ST columns of `AdvLootActions` need the patched `uifiles\default\EQUI_LootFiltersWnd.xml` (two columns after Remove) and `EQUI_AdvancedLootWnd.xml` (two columns after NPC Name); without them those windows stay stock.

## Build

Visual Studio 2022 with the C++ workload. Run `build.bat`; output goes to `bin\`.

## Install

Copy `bin\dinput8.dll` and `dinput8.ini` next to `eqgame.exe`, then turn features on in `dinput8.ini`.

## Check a client without running it

`bin\eqcore_check.exe <path\to\eqgame.exe>` resolves every feature against the file (read-only) and prints
OK/FAIL per feature.
